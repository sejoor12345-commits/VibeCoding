# 리뷰 점검표

## 🔴 1. 보안 (항상 가장 먼저, 가장 심각하게)

- API 키, 비밀번호, 토큰이 코드에 직접 적혀 있지 않은가
  (키는 Colab 보안 비밀 → 환경 변수로만 읽어야 한다. `Study-04/CLAUDE.md` 참고)
- 키가 화면, `print`, 로그, 오류 메시지, 브라우저(HTML/JS)로 새어 나가지 않는가
- `.env` 같은 비밀 파일이 `.gitignore`에 들어 있는가
- 실명, 부대 정보 같은 개인정보가 코드나 테스트 데이터에 들어 있지 않은가 (가명 A, B, C를 쓴다)
- 사용자 입력을 그대로 HTML에 넣지 않는가 (`innerHTML`에 입력값을 넣으면 스크립트가 실행될 수 있다)

## 🔴 2. 버그

- 조건이 반대로 쓰였거나(`>` ↔ `<`, `and` ↔ `or`), 범위가 하나 어긋나지 않았는가 (`range(1, n)`, `<=` 등)
- 경계값: 빈 목록, 0, `None`/`null`/`undefined`, 빈 문자열일 때 멈추거나 이상하게 동작하지 않는가
- 0으로 나누기, 없는 키/인덱스 읽기, 숫자와 문자열 섞어 계산하기 (`"3" + 1`)
- 예외 처리: 앱이 멈출 수 있는 곳은 없는가, 반대로 `except: pass`처럼 오류를 삼켜서 원인을 숨기지 않는가
- 외부에서 오는 값(사용자 입력, 파일, AI 응답, `localStorage`)은 형식이 틀릴 수 있다고 보고 확인하는가
- 상태 관리: 화면이 다시 그려질 때 값이 사라지거나 섞이지 않는가
  (예: Streamlit `st.session_state`, 브라우저 `localStorage`)
- 잘못된 변수 사용, 오타 난 이름, 정의되기 전에 쓰는 변수

## 🟡 3. 코딩 규칙과 읽기 쉬움

- `CLAUDE.md`에 적힌 규칙과 구조를 따르는가
  (예: 계산 로직은 화면(DOM)을 건드리지 않는 함수로 분리, 폴더끼리 코드 공유 안 함)
- 주변 코드와 같은 스타일인가: 이름 짓는 방식, 한국어 주석의 양과 말투, 함수 크기
- 이름만 보고 역할을 알 수 있는가 (`a`, `tmp`, `data2` 같은 이름)
- 같은 코드가 여러 번 복사돼 있지 않은가, 쓰지 않는 코드나 변수가 남아 있지 않은가
- 한 함수가 너무 많은 일을 하지 않는가

## 🟢 4. 성능

- 반복문 안에서 같은 일을 매번 다시 하지 않는가 (파일 다시 읽기, 같은 계산 반복, API 반복 호출)
- 필요 없이 큰 데이터를 보내거나 저장하지 않는가 (예: AI에 보내는 이미지 크기)
- 이득이 작고 코드만 복잡해지는 최적화라면 "지금은 그대로 두는 게 낫다"고 말한다

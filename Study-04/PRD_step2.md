# PRD 2단계: 재료 목록 → 레시피 생성

> 냉장고 재료 인식 & 레시피 추천 웹 앱 (3단계 중 2단계)
> 관련 문서: [PRD_step1.md](PRD_step1.md) (재료 인식), [PRD_step3.md](PRD_step3.md) (프로필 & 레시피 저장)
> 전제: 1단계가 완료되어 사진 → 재료 목록(수정 가능한 입력칸)까지 동작한다.

## 1. 목표

1단계에서 얻은 재료 목록으로 AI가 **지금 바로 만들 수 있는 레시피**를 추천한다. 냉장고에 있는 재료를
최대한 활용하고, 부족한 재료는 따로 알려준다.

## 2. 사용 흐름

```
[1단계] 사진 업로드 → 재료 인식 → 재료 입력칸 (사용자가 수정 가능)
                                          │
[2단계]                     조건 선택 (인분, 시간, 난이도, 개수)
                                          │
                                  "레시피 추천받기" 버튼
                                          │
                              레시피 카드 1~3개 표시
```

- 사진 없이 재료 입력칸에 직접 재료를 써도 레시피를 받을 수 있다.

## 3. 범위

### 포함
- 1단계 재료 입력칸의 내용을 입력으로 사용
- 조건 선택: 인분, 조리 시간, 난이도, 추천 개수
- `stealth/space-bunny-alpha` 모델로 레시피 생성
- 레시피를 카드 형태로 보기 좋게 표시
- 같은 조건으로 "다른 레시피 보기" (다시 생성)

### 제외
- 레시피 저장, 프로필에 따른 맞춤 추천: 3단계
- 레시피 사진 생성
- 영양 성분, 칼로리 계산
- 장보기 목록 만들기

## 4. 기능 요구사항

### F1. 입력 조건
| 항목 | 형태 | 기본값 |
|---|---|---|
| 재료 목록 | 1단계의 재료 입력칸 (쉼표 구분) | 1단계 인식 결과 |
| 인분 | 1~4 선택 | 2인분 |
| 조리 시간 | 15분 이내 / 30분 이내 / 상관없음 | 30분 이내 |
| 난이도 | 쉬움 / 보통 / 상관없음 | 쉬움 |
| 추천 개수 | 1~3 | 3 |

- 재료 목록이 비어 있으면 버튼을 눌렀을 때 "재료를 한 개 이상 입력해주세요"를 띄우고 요청하지 않는다.

### F2. 레시피 생성 요청
- 1단계와 같은 `openrouter_client.py`의 공통 함수로 요청한다 (텍스트만 보냄, 이미지는 다시 보내지 않음).
- AI에게 아래 규칙을 지키도록 요청한다 (프롬프트에 포함):
  - 주어진 재료를 **최대한 많이** 쓰는 레시피를 우선한다
  - 소금, 후추, 설탕, 간장, 식용유, 물은 **집에 있다고 가정**하고 따로 부족 재료로 치지 않는다
  - 그 밖에 목록에 없는 재료가 필요하면 `missing_ingredients`에 적는다 (레시피당 최대 2개)
  - 조리 순서는 초보자도 따라 할 수 있게 한 단계에 한 동작씩 쓴다
  - 추천 레시피끼리 서로 겹치지 않게 한다 (예: 볶음밥 3개 X)
  - **반드시 아래 JSON 형식으로만** 답한다

```json
{
  "recipes": [
    {
      "title": "대파 달걀볶음밥",
      "summary": "남은 밥과 대파로 10분 만에 만드는 볶음밥",
      "servings": 2,
      "time_minutes": 15,
      "difficulty": "쉬움",
      "used_ingredients": ["달걀 2개", "대파 1/2대", "밥 2공기"],
      "missing_ingredients": [],
      "steps": [
        "대파를 잘게 썬다.",
        "달군 팬에 기름을 두르고 대파를 볶아 파기름을 낸다.",
        "..."
      ],
      "tip": "밥은 찬밥을 쓰면 덜 질어진다."
    }
  ]
}
```

- 생성하는 동안 버튼을 비활성화하고 "레시피 만드는 중..."을 보여준다.

### F3. 레시피 표시
- 레시피마다 카드 하나로 보여준다:
  - 제목, 한 줄 소개
  - ⏱ 조리 시간 · 👤 인분 · 난이도
  - 사용하는 재료 (냉장고에 있는 것)
  - **부족한 재료** (있으면 눈에 띄게 따로 표시, 없으면 "냉장고 재료만으로 가능!" 표시)
  - 조리 순서 (번호 목록)
  - 팁
- Gradio의 Markdown 출력으로 그린다.

### F4. 다시 생성
- "다른 레시피 보기" 버튼: 같은 재료와 조건으로 다시 요청한다.
- 이때 방금 보여준 레시피 제목들을 프롬프트에 넣어 "이 레시피들은 제외"하도록 한다.

### F5. 결과 보관 (화면 안에서만)
- 마지막으로 생성한 레시피 JSON을 앱 상태(`gr.State`)에 들고 있는다.
- 3단계의 "저장" 기능이 이 데이터를 그대로 쓸 수 있도록, 화면용 글자가 아니라 **JSON 원본**을 보관한다.

## 5. 오류 처리

- API 관련 오류(키 없음, 401, 404, 429, 시간 초과)는 1단계와 같은 메시지를 쓴다 (`openrouter_client.py` 공통 처리).
- AI 답이 JSON이 아니거나 필수 항목(`title`, `steps`)이 빠진 레시피는 버리고, 남은 레시피만 보여준다.
  하나도 남지 않으면 "레시피를 만들지 못했어요. 다시 시도해주세요"를 띄운다.
- 재료 목록에 음식이 아닌 것만 있으면(예: "휴대폰, 컵") AI가 빈 `recipes`를 돌려주도록 하고,
  "이 재료로는 레시피를 만들기 어려워요"를 띄운다.

## 6. 파일 구조 (2단계 완료 시점)

```
Study-04/fridge_recipe/
├── app.py               # 2단계 화면(조건 선택, 버튼, 레시피 카드) 추가
├── openrouter_client.py # (1단계) 공통 요청 함수 — 수정 없음
├── vision.py            # (1단계) 재료 인식
└── recipe.py            # 레시피 프롬프트 만들기 + JSON 해석 + 카드용 Markdown 만들기
```

## 7. 완료 기준

- [ ] 1단계에서 인식한 재료로 "레시피 추천받기"를 누르면 레시피 카드가 선택한 개수만큼 나온다.
- [ ] 각 레시피에 사용 재료, 부족한 재료, 조리 순서가 표시된다.
- [ ] 소금·간장 같은 기본 양념은 부족한 재료에 나오지 않는다.
- [ ] 조건(15분 이내, 쉬움)을 바꾸면 결과가 그 조건에 맞게 바뀐다.
- [ ] "다른 레시피 보기"를 누르면 이전과 다른 레시피가 나온다.
- [ ] 사진 없이 재료를 직접 입력해도 레시피가 나온다.
- [ ] 재료 입력칸이 비어 있으면 요청하지 않고 안내 메시지가 뜬다.

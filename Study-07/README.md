> 내 진짜 코드에서 꺼낸 버그 25개로 **직접 고치는 손**을 기르는 연습장이에요.
> 설치도 터미널도 필요 없어요. 브라우저 하나면 돼요.

중간 점검(2026-10-07)에서 찾은 가장 약한 곳이 **"직접 고치기 · 디버깅"** 이었어요. 지금까지 커밋의 약 90%는 Claude가 했어요.
해커톤에서는 시간이 없을 때 내가 직접 버그를 잡아야 해요. 그래서 남이 만든 예제가 아니라
**내 앱들(운동 앱 · AI 연말정산 · 근무표 · 사지방 런처)의 코드**를 짧게 잘라서 문제로 만들었어요.

## 하루 10분 쓰는 법

1. **오늘의 1문제** 탭을 눌러요. 안 푼 문제 중 가장 쉬운 게 나와요(다 풀면 복습 문제).
2. **1분** — 상황(이야기)과 테스트 목록을 읽어요.
3. **2분 · ① 예상하기** — "실행하면 무엇이 나올까?", "몇 번째 줄이 범인일까?"를 적어요. 안 적으면 실행 버튼이 안 눌려요(일부러).
4. **4분 · ② 실행** — 편집기에서 **한 곳만** 고치고 실행 → ✅/❌와 기대·실제 값을 비교해요. 막히면 힌트 1 → 힌트 2 → 정답 순서로.
5. **2분 · ③ 비교** — 예상과 무엇이 달랐는지 보고, 이 버그를 **내 말로 한 줄** 적어요. 그 한 줄이 **내 버그 도감**에 쌓여요.
6. **1분(PC라면)** — F12를 열어 같은 코드를 콘솔에서 만져 보거나, 편집기에 `debugger;`를 넣고 실행해 Sources 탭에서 멈춰 봐요.

- 처음이면 **5단계 · F12** 탭부터 3분만 읽어요: 재현 → 범위 좁히기 → 가설 → 한 가지만 바꾸기 → 확인, 그리고 F12 쓰는 법.
- 점수: 문제마다 ★ × 10점, 힌트 하나에 3점씩 빠지고, 정답을 보면 반. **연속 일수**는 하루에 1문제 이상 푼 날을 세요.
- 기록은 브라우저(localStorage)에 저장돼요. **사지방 PC는 재시작하면 지워질 수 있어서**, 끝날 때 **내 도감 → 진행 기록 옮기기 → 복사하기**로 노션에 붙여 두고, 다음에 붙여넣고 **불러오기** 하세요.

## 새 문제 추가하기 (앞으로 만날 진짜 버그로)

버그를 만나면 먼저 **내 도감 → 직접 만난 진짜 버그 적기**에 "어디서 · 증상 · 원인"을 적어 두세요. 나중에 Claude에게
"이 버그로 도장 문제 하나 만들어 줘"라고 하거나, 아래 틀대로 `index.html`에 직접 넣으면 돼요 (GitHub 웹 편집기로 가능).

**① 코드 두 덩어리** — `index.html`의 `<!-- ===================== 문제 코드` 아래, 다른 문제들 사이에 붙여요.

```html
<script type="text/plain" data-ex="my-new-bug" data-part="bug">
// 버그가 있는 코드 (혼자 돌아가게 짧게, 10~20줄)
function addOne(n) {
  return n + "1";
}
</script>
<script type="text/plain" data-ex="my-new-bug" data-part="fix">
// 고친 코드 (버그 코드와 한 곳만 다르게)
function addOne(n) {
  return n + 1;
}
</script>
```

테스트에 가짜 저장소 · 가짜 인터넷 같은 준비 코드가 필요하면 `data-part="prelude"` 덩어리를 하나 더 만들어요 (4번 · 24번 참고).

**② 설명 한 덩어리** — `const EXERCISES = [` 목록에서 난이도 순서에 맞는 자리에 넣어요.

```js
{
  id: 'my-new-bug', level: 1, cat: 'type',          // cat은 CATS 목록의 이름 중 하나
  title: '화면에 보일 제목 (증상으로)',
  source: { repo: '저장소 이름', file: '파일 경로', fn: '함수 이름' },
  story: '어떤 화면에서 무엇을 했더니 무엇이 나왔는지 1~2줄',
  tests: [
    { name: '테스트 이름', run: `addOne(1)`, expect: 2 },      // run = 실행할 식, expect = 나와야 하는 값
  ],
  hints: ['힌트 1: 어디를 볼까', '힌트 2: 무엇이 틀렸나'],
  explain: '정답 설명 (왜 틀렸고, 다음에 어떻게 알아챌까)',
  python: 'Python으로 치면 …',
  real: { kind: 'fixed', text: '어느 커밋 · 언제 실제로 일어났는지' },   // fixed · live · notes · whatif
},
```

**③ 확인** — 버그 코드는 테스트를 1개 이상 틀리고, 정답은 모두 통과해야 해요. 브라우저에서 그 문제를 열어
편집기에 정답을 직접 넣고 ② 실행으로 확인할 수 있어요. Claude에게 맡길 때는 "`verify.mjs`로 확인해 줘"라고 하면 문제 전부를 한 번에 돌려 봐요.

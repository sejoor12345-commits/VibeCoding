이 명령어는 아래 7단계를 **반드시 순서대로** 실행한다. 각 단계에는 "검증"과 "실패 조건"이
있다. 검증을 통과해야만 다음 단계로 넘어가고, **어느 단계든 실패 조건에 걸리면 그 즉시 멈추고
다음 단계는 실행하지 말고** 맨 아래 "오류 보고 형식"대로만 보고해라. 7단계를 전부 통과했을
때만 "실행 결과 보고 형식"으로 보고해라.

## 1단계: 문제 파일 구조 읽고 이해하기

`Study-03/questions.js`를 전부 읽어라.

- **검증**: 파일이 존재하고, `const questions = [ ... ];` 배열을 정의하며, 배열의 각 원소가
  `{ id, category, difficulty, hasHint, question, choices[4], answerIndex, explanation }` 형태를
  따르는지 확인해라.
- **실패 조건**: 파일이 없거나, `questions` 배열을 찾을 수 없거나, 파일에 문법 오류가 있거나,
  원소 형태가 위와 다르면 실패다.

## 2단계: 현재 문제 개수와 분포 확인

전체 문제 수, 카테고리별 문제 수, 난이도별 문제 수, 카테고리 x 난이도 16칸 각각의 문제 수를
계산해라 (`/quiz-stats`와 같은 방식).

- **검증**: 카테고리별 합계와 난이도별 합계가 각각 전체 문제 수와 일치하고, 16칸의 합도 전체
  문제 수와 일치해야 한다. `id`에 중복이나 빠진 번호가 없어야 한다.
- **실패 조건**: 위 합계 중 하나라도 안 맞거나 `id`에 중복/결번이 있으면 실패다.

## 3단계: 카테고리별로 부족한 부분 파악

2단계의 16칸 표에서 **문제 수가 가장 적은 칸**을 찾아라. 여러 칸이 동률로 최소면
`한국사 > 과학 > 일반상식 > 의학` 순서, 그 안에서 `하 > 중 > 상 > 최상` 순서로 먼저 오는 칸을
오늘의 목표로 정해라.

- **검증**: 정한 목표의 카테고리와 난이도가 실제 `CATEGORIES`/`DIFFICULTIES` 값과 정확히
  일치해야 한다.
- **실패 조건**: 2단계 데이터가 없어서 16칸 표를 만들 수 없거나, 목표를 하나로 정할 수 없으면
  실패다.

## 4단계: 새 문제 추가 전 중복 체크

3단계에서 정한 카테고리+난이도 기존 문제를 전부 읽고, 같은 주제·사실을 다루는 문제가
`questions.js` 전체(다른 칸 포함)에 이미 있는지 살피며 새 문제 1개를 초안으로 만들어라 (작성
규칙은 `quiz-add.md`의 "새 문제 작성" 항목과 동일).

- **검증**: 초안이 다루는 주제·정답·사실이 기존 161개 문제 중 어느 것과도 겹치지 않아야 한다.
- **실패 조건**: 겹치지 않는 초안을 최대 3번 시도해도 만들 수 없으면 실패다.

## 5단계: 문제 추가 후 형식 검증

4단계 초안을 실제로 `questions.js`에 추가해라. 삽입 방식은 `quiz-add.md`의 "파일에 삽입"
항목과 동일하다 (해당 `// ===== ... =====` 블록 끝에 추가, `id`는 전체 최대 id + 1, 파일 위
총 문제 수 주석과 `Study-03/CLAUDE.md`의 문제 수 언급도 함께 갱신).

추가한 뒤 아래를 모두 다시 확인해라.

- `choices`가 정확히 4개이고 서로 중복되지 않는다.
- `answerIndex`가 0~3 범위이며 실제로 맞는 정답을 가리킨다.
- `hasHint`가 규칙(최상=`false`, 그 외=`true`)과 맞는다.
- `id`가 기존 id와 중복되지 않고 전체 최댓값 + 1이다.
- `Study-03/CLAUDE.md`의 "퀴즈 문제 교차 검증 가이드라인" 4개 항목을 모두 통과한다.
- 파일 전체가 여전히 문법적으로 유효한 자바스크립트다 (직접 실행해서 `questions` 배열을 다시
  불러와 확인해라).

- **검증**: 위 항목이 전부 통과해야 한다.
- **실패 조건**: 하나라도 통과하지 못하면, **방금 추가한 문제를 파일에서 되돌려(추가 전 상태로
  복원한) 뒤** 실패로 처리한다.

## 6단계: 전체 데이터 백업

5단계까지 통과했다면, 지금 상태의 `Study-03/questions.js` 전체를
`Study-03/.claude/backups/questions.js.<YYYYMMDD-HHMMSS>.bak` 경로로 그대로 복사해 백업해라
(`Study-03/.claude/backups/` 폴더가 없으면 새로 만들어라).

- **검증**: 백업 파일이 실제로 생성됐고, 그 내용이 방금 수정한 `questions.js`와 한 글자도 다르지
  않아야 한다.
- **실패 조건**: 백업 파일을 만들지 못했거나 내용이 다르면 실패다. 단, 이 시점에는 5단계까지
  이미 정상 통과해 문제가 정상적으로 추가된 상태이므로, 백업 실패라고 해서 방금 추가한 문제를
  되돌리지는 말고 오류로만 보고해라.

## 7단계: 실행 결과 상세 보고

7단계까지 전부 통과했을 때만 아래 형식으로 보고해라.

```
## 실행 결과 보고
1단계 (구조 확인): 통과
2단계 (개수/분포): 전체 N개, 카테고리별 {...}, 난이도별 {...}
3단계 (부족 부분): {카테고리}-{난이도} 칸이 M개로 가장 적어 오늘의 목표로 선정
4단계 (중복 체크): 통과, 초안 주제: "..."
5단계 (형식 검증): 통과, 새 문제 id={새id}
6단계 (백업): Study-03/.claude/backups/questions.js.{타임스탬프}.bak 생성 완료
- 새로 추가된 문제: id / category / difficulty / question / 정답 선택지 / explanation
- 추가 전 → 추가 후 카테고리 x 난이도 16칸 표
```

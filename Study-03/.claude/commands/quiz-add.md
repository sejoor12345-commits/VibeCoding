카테고리: $1
난이도: $2

`Study-03/questions.js`의 `questions` 배열과 `Study-03/CLAUDE.md`의 "퀴즈 문제 교차 검증 가이드라인"
항목을 읽어라.

## 인자 검증

- `$1`, `$2` 중 하나라도 비어있으면, 어떤 값을 받았는지 알려주고 "예: /quiz-add 과학 중"처럼 사용법을
  안내한 뒤 멈춰라.
- `$1`이 실제 카테고리(한국사, 과학, 일반상식, 의학) 중 하나와 정확히 일치하지 않으면, 받은 값과 실제
  카테고리 4개를 알려주고 멈춰라.
- `$2`가 실제 난이도(하, 중, 상, 최상) 중 하나와 정확히 일치하지 않으면, 받은 값과 실제 난이도 4개를
  알려주고 멈춰라.

## 새 문제 작성

1. 해당 category+difficulty의 기존 문제를 전부 읽고, 주제나 사실이 겹치지 않는 새 문제를 1개 만들어라.
2. 난이도 기준에 맞춰라: 하=초등학생, 중=고등학생, 상=대학생, 최상=그 분야를 공부하는 사람이 풀 만한
   수준.
3. 기존 문제와 같은 형식을 그대로 따라라: `{ id, category, difficulty, hasHint, question,
   choices[4], answerIndex, explanation }`. 선택지는 정확히 4개, 오답도 그럴듯하지만 명백히 틀리게
   만들어라.
4. `hasHint`는 난이도가 "최상"이면 `false`, 그 외(하/중/상)에는 `true`로 설정해라 (기존 규칙).
5. `explanation`은 정답의 근거를 한두 문장으로 써라.

## 교차 검증 가이드라인 준수 (필수 — 하나라도 통과 못 하면 파일에 추가하지 말고 문제를 고쳐서
다시 점검해라)

작성한 문제를 아래 4가지에 하나씩 맞춰 스스로 점검해라.

1. **정답이 하나뿐인가?** 다른 해석이 가능하면 "면적 기준", "2024년 기준"처럼 조건을 문장에
   명시해라.
2. **최상급 표현에 기준이 있는가?** "가장", "최초", "최대", "최소", "최고", "최상", "제일", "유일",
   "처음" 같은 표현을 썼다면 반드시 측정/판단 기준을 문장에 넣어라.
3. **시간과 범위가 명확한가?** 바뀔 수 있는 정보는 기준 시점을 밝히고, 지리적·분류적 범위를
   한정해라.
4. **교차 검증했는가?** 확신이 서지 않는 사실은 신뢰할 수 있는 근거로 다시 확인하고, 논란이 있는
   내용은 주류 학설을 기준으로 써라.

## 파일에 삽입

- `questions.js`에서 `// ===== {category} - {difficulty} (...) =====` 주석으로 시작하는 블록을
  찾아, 그 블록의 마지막 문제 바로 뒤(다음 블록 주석 앞)에 새 문제 객체를 삽입해라.
- 새 문제의 `id`는 기존 id를 절대 바꾸지 말고, **`questions` 배열 전체에서 가장 큰 id + 1**로
  부여해라.
- 그 블록의 `// ===== ... (n~m) =====` 범위 주석 끝에 새로 추가된 id를 알아보기 쉽게 덧붙여라
  (예: `// ===== 과학 - 중 (51~60, 161 추가) =====`).
- 파일 맨 위 주석의 총 문제 수(예: "총 160문제")를 새 총 개수로 고쳐라.
- `Study-03/CLAUDE.md`에 있는 총 문제 수·카테고리별 문제 수 언급(예: "160문제", "10문제씩")도 실제
  문제 수와 어긋나지 않도록 함께 고쳐라.

## 마무리

- 추가한 문제의 `id`, `category`, `difficulty`, `question`, 정답 선택지, `explanation`을 표로
  보여줘라.
- 교차 검증 가이드라인 4개 항목을 각각 어떻게 통과시켰는지 한 줄씩 요약해라.
- 마지막에 "새 문제 id, 추가된 위치(카테고리·난이도), 새 전체 문제 수"를 한 줄로 요약해라.

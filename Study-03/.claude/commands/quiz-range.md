시작id: $1
끝id: $2

`Study-03/questions.js`의 `questions` 배열을 읽어라.

- `$1`, `$2`가 둘 다 숫자가 아니거나 비어있으면, 어떤 값을 받았는지 알려주고 "예: /quiz-range 121 160"
  처럼 사용법을 안내한 뒤 멈춰라.
- `$1`이 `$2`보다 크면, 두 값을 알려주고 순서가 바뀐 것 같다고 안내한 뒤 멈춰라.
- `id`가 `$1` 이상 `$2` 이하인 문제만 검토 대상으로 삼아라. 해당하는 문제가 하나도 없으면, 실제
  `questions` 배열의 id 범위(최소~최대)를 알려주고 멈춰라.

검토 대상 문제 각각에 대해 아래를 표로 정리해라:
- `id`, `category`, `difficulty`, `answerIndex`(0부터 시작하므로 몇 번째 선택지인지 사람이 읽기
  쉽게 "1번" ~ "4번"으로 바꿔서 표시)

그 다음 두 가지 분포를 계산해서 보여줘라.

1. **난이도 분포**: 검토 대상 안에서 하/중/상/최상 각각 몇 문제인지, 전체 대비 비율(%)과 함께 표로
   보여줘라.
2. **정답 분포**: 검토 대상 안에서 정답이 1번/2번/3번/4번 선택지인 문제가 각각 몇 개인지, 전체 대비
   비율(%)과 함께 표로 보여줘라. 문제 수가 4의 배수에 가깝다면 이상적으로는 각 번호가 25%에 가까워야
   한다는 점을 기준으로, 특정 번호(특히 1번처럼 맨 앞)가 눈에 띄게 많거나 적으면(예: 다른 번호의 2배
   이상 차이) "정답이 특정 번호에 몰려있어서 문제를 안 풀어도 찍을 때 유리할 수 있다"고 짚어주고, 어떤
   문제의 `answerIndex`를 다른 선택지와 자리를 바꾸면 분포가 고르게 될지 구체적으로 제안해라. 뚜렷한
   쏠림이 없으면 "쏠림 없음"이라고 짧게 알려줘라.

마지막에 "검토한 문제 수, 난이도 분포 요약, 정답 분포 요약"을 한 줄로 요약해라. 문제 파일을 고치지는
말고, 표와 제안만 보여줘라.
